# 模型可用性监控设计

状态：第一阶段 NewAPI 监控内核和第二阶段管理端页面均已完成、生产热切并验证；后续为 AI Balance 插件和独立的模型级路由阶段
范围：NewAPI 为监控控制面，TrafficMonitor AI Balance 插件为只读展示端
日期：2026-07-26

## 1. 目标

为关注的中转模型建立按站点、渠道和模型可追溯的可用性监控。系统需要同时回答：

- 某个站点当前是否正常、受限或不可用？
- 站点内的 GPT、Grok 等模型家族及免费/收费模型是否可用？
- 具体是哪条 `渠道 + 模型` 路径失败、受限或被风控？
- 首字时间、完整耗时、可用率和探测成本如何变化？
- 上游模型单价或分组倍率变化后，历史探测成本如何保持可复核？

NewAPI 负责采集、调度、持久化、权限和管理界面。AI Balance 插件只读取已聚合的监控结果，不持有上游密钥，不直接向上游发起探测。

## 2. 明确不做的事

第一期不做以下行为：

- 不因监控结果自动禁用渠道、密钥或模型。
- 不修改 NewAPI 现有路由、优先级、重试或回退逻辑。
- 不把监控探测作为普通用户请求处理，也不让插件直接扇出请求。
- 不持久化 API Key、Authorization、Cookie、完整请求体或完整上游响应体。
- 不将本地静态价格表伪装为上游实际计费。

模型级路由屏蔽或自动降级可以在第二期消费本监控数据，但必须作为单独功能设计和验证。

## 3. 术语和层级

```text
监控站点 (site)
  -> NewAPI 渠道 (channel)
    -> 对外模型 (public model)
      -> 映射后的上游模型 (upstream model)
        -> 探测路径 (site + channel + public model)
```

- **监控站点**：同一上游服务的人工确认分组。一个站点可包含多个 NewAPI 渠道。
- **渠道**：NewAPI 中实际配置密钥、Base URL、模型映射和路由属性的渠道。
- **对外模型**：NewAPI 用户实际请求的模型名，也是关注清单和权重的主体。
- **上游模型**：通过渠道模型映射最终发送给上游的模型名。
- **探测路径**：一个具体的 `站点 + 渠道 + 对外模型` 组合，是最低层观测单位。
- **有效站点模型**：同一站点内同一对外模型跨渠道路径折叠后的结果。它只计一次模型权重。

监控站点归属由管理员人工确认。系统可根据规范化 Base URL 提示候选分组，但不得自动合并渠道：相同 URL 下的不同账号、Key 或用户组可能有不同的余额、倍率、风控和可用性。

## 4. 模型分类和权重

模型分类复用 NewAPI 现有模型目录和价格目录的元数据，至少包括：

- 供应商和家族，例如 OpenAI/GPT、xAI/Grok、Google/Gemini、Anthropic/Claude。
- 输入输出模态，例如文本、图像、音频、视频、文件。
- 能力，例如流式、推理、视觉和工具调用。
- 支持端点类型，例如 Responses 或 Chat Completions。

分类用于聚合、筛选和展示，不应由监控功能重复维护一份基于名称的猜测规则。

免费/收费不是全局模型属性，而是 `站点 + 渠道 + 模型` 的上游定价属性。相同 GPT 模型在不同站点可能免费、收费或具有不同倍率，因此该分类来自上游定价快照。

每个关注模型配置 `1-5` 的业务权重，默认值为 `1`。模型权重用于站点健康分；厂商、能力和收费分类不替代权重。

图像模型独立汇总和展示，不与文本模型健康分混算。第一期文本监控只覆盖可以执行最小流式文本请求的模型路径。

## 5. 可用性状态

### 5.1 单次观测状态

每一条业务观测或主动探测保存以下归类：

- **可用**：请求成功，并获得有效的模型输出。
- **受限**：429、额度不足、风控、区域或策略限制等。链路可达，但当前不能稳定提供服务。
- **不可用**：认证失败、模型不存在、上游 5xx、连接失败或超时。
- **未知**：尚未观测、任务排队、进入退避，或数据已过期。

探测提示词可请求固定短内容用于诊断，但可用性判断以协议成功和有效输出为准，不要求逐字匹配。

### 5.2 业务观测和主动探测

可用性以业务观测优先，主动探测补盲：

- **业务观测**：正常请求实际命中某个 `渠道 + 模型` 后产生的成功、上游可归因失败、首字时间和完整耗时。它没有额外探测成本。
- **主动探测**：用于没有近期业务观测的关注模型，以及失败后的恢复验证。

用户参数错误、客户端取消、与上游无关的本地校验失败和内容拒绝不得污染渠道模型健康度。

两类观测必须携带来源标识。第一期只观测，不改变路由。

### 5.3 抗抖动规则

页面同时展示最近一次结果和派生健康状态：

- 最近一次上游结构性失败立即显示为异常事件。
- 连续 3 次独立结构性失败后，派生状态为不可用。
- 连续 2 次成功后，派生状态恢复为可用。
- 429、余额不足和风控直接派生为受限，不混入网络或服务故障。
- 新建模型在观察宽限期内保持未知；超过宽限期仍未观测时视为数据过期。

## 6. 首字时间和时延

文本模型探测使用其实际支持的流式端点，并记录：

- 请求开始时间。
- 首个有效上游流事件到达时间，即首字时间。
- 完整响应结束时间，即完整耗时。
- 首事件后断流、首事件超时和完整响应超时等独立故障类型。

端点由 NewAPI 模型目录的 `supported_endpoint_types`、渠道类型和已配置模型映射决定。监控必须严格测试选定的实际端点；失败时不得自动换用另一个端点掩盖问题。特殊协议或映射允许在关注模型配置中显式指定端点类型。

不支持流式的路径首字时间显示为不适用，不填充伪造数值。

## 7. 定价、倍率和探测成本

### 7.1 定价来源

上游 NewAPI 和 sub2api 类站点可能提供模型单价、缓存单价、分组倍率或实际扣费信息，且这些信息会变化。监控使用如下优先级：

1. 上游单次请求或上游用量记录提供实际扣费时，保存为实际成本。
2. 上游定价接口提供模型价格和分组倍率时，结合本次 Token 用量计算成本，标记为按上游定价估算。
3. 无法取得上游定价时，成本标记为未知，不回退为本地静态价格。

每次观测要引用当时的定价快照，包括输入、输出、缓存、缓存创建等单价和适用的分组倍率。后续上游修改倍率只能影响新记录，不能重算历史。

### 7.2 上游适配器

站点创建时由管理员显式选择 `NewAPI` 或 `sub2api` 类型。可以提供检测按钮给出建议，但管理员必须确认类型。

每种站点类型使用独立的模型目录和定价适配器，不使用多端点静默回退。定价同步失败时：

- 标记定价同步异常。
- 保留上一个有效定价快照及其版本和时间。
- 不影响可用性探测和已有历史成本。

实现前必须针对用户实际使用的 NewAPI/sub2api 版本，验证模型、分组和定价接口的字段、认证方式、缓存语义及实际扣费可得性。

## 8. 调度和风控边界

主动探测由 NewAPI 后台任务执行，插件和浏览器的刷新操作只能请求入队。

调度原则：

- 正常业务请求优先于监控任务。
- 同一站点最多 1 个主动探测同时执行。
- 全局最多 2 个主动探测同时执行。
- 同一站点两次主动请求至少间隔 10 秒。
- 429、风控、连接超时和上游错误使用指数退避。
- 相同监控任务运行或排队时，重复手动刷新合并，不重复启动。
- 有新的有效业务观测时，推迟该模型的主动补盲请求。

默认补盲目标：

| 模型权重 | 无近期业务观测时的目标补探间隔 |
| --- | --- |
| 5 | 5 分钟 |
| 3-4 | 15 分钟 |
| 1-2 | 30 分钟 |

以上是尽力而为的目标，不是业务高峰时必须完成的 SLA。数据可变旧，但监控不得抢占正常请求并发。

## 9. 聚合、评分和任务栏颜色

### 9.1 同模型多渠道折叠

同一站点同一对外模型可能经由多个渠道提供。底层继续保留每条探测路径的结果；站点评分前折叠为有效站点模型：

- 任一路径可用：该模型在本站点可用。
- 无可用路径但存在受限路径：该模型受限。
- 全部路径不可用：该模型不可用。

一个对外模型只计一次权重，不能因为配置多个备用渠道被重复放大。详情页展示主路径、备用路径和实际业务主要命中的渠道。

### 9.2 加权健康分

文本模型站点健康分为有效站点模型的权重加权平均：

- 可用：100 分。
- 受限：50 分。
- 不可用：0 分。
- 观察宽限期内的未知：不进入分母。
- 宽限期后的未知或过期：50 分。

任务栏只展示站点名称和站点级颜色：

- **白色**：健康分 100。
- **黄色**：健康分 50-99。
- **红色**：健康分低于 50，或所有关注模型均不可用。

图像状态独立显示和告警，不改变文本模型健康分。

## 10. 存储和保留

建议保存以下逻辑实体：

- `model_monitor_sites`：站点名称、显式站点类型、状态、设置和更新时间。
- `model_monitor_site_channels`：站点与 NewAPI 渠道的人工确认关系。
- `model_monitor_targets`：关注对外模型、端点类型、权重、启用状态和覆盖配置。
- `model_monitor_observations`：业务观测或主动探测的路径级原始结果、状态、时延、Token 用量、脱敏错误摘要和定价快照引用。
- `model_monitor_price_snapshots`：站点、账号/分组适用范围、模型价格、倍率、来源、版本和采集时间。
- `model_monitor_aggregates_hourly`：一小时粒度的可用率、首字时间、完整耗时、失败分类和探测成本汇总。
- `model_monitor_jobs`：入队、运行、合并、退避和完成状态。

保留策略：

- 原始单次观测保留 30 天。
- 一小时聚合长期保留。
- 详情页展示 1 小时、24 小时和 7 天的可用率、P95 首字时间、P95 完整耗时、失败分类和成本趋势。

## 11. 权限和数据保护

监控接口不通过普通 `/v1` 用户 API Key 暴露。AI Balance 插件复用 NewAPI 管理端登录会话。

新增最小权限：

- `model-monitor.read`：读取汇总、详情、历史和已脱敏诊断。
- `model-monitor.operate`：手动入队监控周期。
- `model-monitor.write`：修改站点、渠道归属、关注模型、权重和调度设置。

所有持久化和返回的错误信息必须先脱敏。允许显示状态分类、HTTP 状态、请求端点、时间、站点/渠道/模型标识和脱敏错误摘要；禁止存储或返回 Key、Authorization、Cookie、完整请求体和完整上游响应体。

深度排障继续使用现有 NewAPI 受控日志和服务器日志，而不将监控库变成敏感报文副本。

## 12. 界面职责

### 12.1 NewAPI 管理端

NewAPI 管理端是权威操作台，负责：

- 监控站点、渠道归属、站点类型和适配器状态。
- 自动模型分类、模型筛选、关注模型、权重和端点覆盖。
- 调度、任务队列、定价同步、定价变化和探测成本。
- 站点、模型、渠道路径详情，包含趋势和失败明细。

### 12.2 TrafficMonitor AI Balance 插件

插件新增可用性页签，只消费 NewAPI 监控 API：

- 站点级红黄白概览。
- 关注模型的当前状态、24 小时可用率和首字时间。
- 精简的模型详情和最近异常。
- 需要完整历史或配置时跳转 NewAPI 管理端详情页。

任务栏空间有限，只显示站点名称和综合颜色；不显示模型、延迟、成本或错误文本。悬停摘要可说明异常模型组。

### 12.3 通知

第一期采用低干扰通知：

- 任务栏反映站点综合状态。
- 首次进入受限或不可用，以及恢复时发送 Windows 通知。
- 按 `站点 + 渠道 + 模型 + 状态` 去重 30 分钟。
- 单次异常、未知、排队和退避不发送通知。

## 13. 对外 API 草案

以下路径是命名草案，具体路由需与当前 NewAPI 权限和 API 规范一致：

- `GET /api/model-monitor/summary`：插件和管理页的站点级摘要。
- `GET /api/model-monitor/sites`：站点列表、评分和适配器状态。
- `GET /api/model-monitor/sites/:site_id`：站点详情、有效模型和渠道路径。
- `GET /api/model-monitor/sites/:site_id/models/:model`：模型时延、可用率、失败和成本详情。
- `GET /api/model-monitor/config`：站点、关注模型、权重和调度配置。
- `PUT /api/model-monitor/config`：修改配置。
- `POST /api/model-monitor/runs`：合并入队一次受控监控周期。
- `POST /api/model-monitor/pricing-snapshots`：由授权普通 Token 或管理员导入脱敏定价目录。
- `POST /api/model-monitor/actual-costs`：按 `站点 + 上游 request_id` 批量导入真实扣费并精确对账。

接口返回必须区分数据新鲜度、观测来源、派生状态、定价来源和成本可信度。

## 15. 验收标准

第一阶段完成前至少验证：

- 同站点多渠道、同模型多路径时，折叠结果和模型权重只计算一次。
- 业务成功、上游失败、用户参数错误、客户端取消、429、风控、超时和首事件后断流均正确分类。
- 首字时间和完整耗时由实际流式响应时间点计算。
- 手动刷新任务合并，站点和全局并发限制生效，业务请求优先。
- 上游定价变更不会重写历史观测成本。
- 所有监控 API 均执行权限检查，错误和日志不泄露敏感凭据。
- 功能关闭时不改变现有路由、渠道状态或正常请求行为。

## 16. 第一阶段 TDD 执行计划

### 16.1 原则

第一阶段按可独立发布和验证的测试切片实施。每个切片必须遵循：

1. 先写只描述外部行为或持久化契约的确定性测试，并确认测试在未实现前失败。
2. 只实现让该测试通过所需的最小生产代码。
3. 运行该切片的聚焦测试并重构重复逻辑，不扩大到未确认的路由或兼容行为。
4. 再运行相邻模块的回归测试，确认功能关闭时既有渠道测试、路由和计费行为不变。

所有数据库测试使用显式初始化的内存 SQLite fixture，并通过 GORM API 保持 SQLite、MySQL 和 PostgreSQL 兼容。测试使用 `require` 做初始化和致命断言，使用 `assert` 验证行为。探测和上游适配器测试使用 `httptest` 固定响应，不依赖真实上游站点、睡眠或不稳定的时序断言。

### 16.2 切片 A：领域模型、迁移和评分

**先写失败测试**

- 创建监控站点、站点渠道归属、关注模型、路径观测和定价快照后，能以站点、渠道、模型和时间查询。
- 同一 `站点 + 渠道` 不能重复归属；同一站点的同一对外模型只生成一个有效站点模型。
- 模型权重只允许 `1-5`；状态、观测来源和站点类型只允许已定义值。
- 有一条可用路径时，有效站点模型为可用；无可用路径但有受限路径时为受限；全部不可用时为不可用。
- 未过观察宽限期的未知不进入评分分母；过期未知按 50 分；加权健康分和红黄白阈值符合第 9 节。
- 新的定价快照不会修改既有观测所关联的定价数据。

**最小实现**

- 在 `model/` 新增模型监控实体、查询函数和纯评分函数。
- 在 `model/main.go` 的正常和快速迁移路径中注册全部监控实体。
- 不接入渠道测试、系统任务、路由、日志或上游 HTTP。

**通过条件**

```powershell
go test ./model -run 'TestModelMonitor|Test.*Monitor'
```

同时补跑已有 `model` 包测试，确认迁移和现有模型缓存测试不受影响。

### 16.3 切片 B：运行时配置和系统任务壳

**先写失败测试**

- 监控总开关默认关闭，关闭时调度器不会创建监控任务。
- 手动入队在没有活动任务时创建一个 `model_monitor` 任务；已有 pending/running 任务时返回同一任务，不创建第二条。
- 任务由现有数据库 lease 保护，过期 lease 后可重新领取。
- 调度间隔到期时只创建一个任务，未到期或总开关关闭时不创建。
- 任务状态和进度不泄露配置中的敏感字段。

**最小实现**

### 16.5 切片 D：上游定价快照适配器

**先写失败测试**

- NewAPI 和 sub2api 的每种实际接口样本都能解析出模型价格、缓存价格、分组倍率和来源版本。
- 未知字段、缺少倍率、认证失败和 WAF 响应不会被错误识别为零成本或免费模型。
- 站点类型必须显式选择；适配器不得对不匹配的站点类型执行静默回退。
- 同步失败时保留上次有效快照，并将同步状态标记为异常。

**最小实现**
